# Contributing and local workflow

Use `main` as the default branch. Create a short-lived branch for each real change, keep commits focused, describe why the change is needed, and run the checks documented in the README before opening a pull request.

Do not commit `.env`, credentials, runtime databases, personal datasets or generated identity templates. Use synthetic examples. Explain AI assistance and independently review generated code. Bug reports should include reproduction steps, expected/actual behavior and sanitized logs.

These are small educational projects. Please discuss broad changes first. No contribution history or production readiness is implied by this workflow.
