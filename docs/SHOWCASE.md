# 六分钟展示路线

定位：个人学习与作品展示。使用合成资料讲清 RAG、Agent、框架组合与企业场景中的权限意识；默认在本机轻量运行。

## 第一分钟：讲清各个概念

|概念|在本项目中的例子|入口|
|---|---|---|
|大模型|可选的模型 API 负责规划或生成；默认回答来自原文抽取|--real、模型适配器|
|RAG|先找资料，再用资料回答，并展示出处|/ask、/chat|
|Embedding|将文字编码为向量，供相似度搜索；默认哈希向量只是词项对照|embedding.py、pgvector|
|Agent|在工具范围内选择知识检索或工单查询；真实规划需要启用模型|/agent|
|LangChain|Document、BaseRetriever、StructuredTool 统一组件接口|langchain_components.py|
|LangGraph|把规划、工具、证据检查和有界纠错组织成有条件分支|workflow.py、corrective.py|
|评测|用固定标注集检验召回、拒答、引用与回归|evaluate.py、check_evaluation.py|

准备一句说明：“我把检索与生成拆开，把权限检查放在检索前，再让工作流在有限步骤内决定继续、拒答或澄清。”

## 第二分钟：检索与纠错

页面输入“报账”，选择 BM25。展开“查看检索过程”，观察第一次检索不足后按小型词典改写为“报销”，最多再检索一次。当前词典明确写在 query_rewrite.py，便于解释和检查。

这展示的是查询改写和工作流分支。它不需要模型训练或额外在线服务。只有存在有用的词典改写才重试；权限和服务异常会直接返回错误。

## 第三分钟：多轮与澄清

先问“差旅报销和入职材料分别有什么要求？”，再问“那具体呢？”。因为上文有两个主题，页面展示可选主题。点击一个主题后再发送问题。

单主题例子：问“差旅报销的规定是什么？”，再问“那期限是几天？”。系统使用当前仍可访问的来源标题补充追问。这个实现便于展示基本指代处理；复杂对话仍需要更完整的模型改写和评测。

## 第四分钟：章节上下文与引用

在“我的资料”上传 data/showcase/section-policy.md，标题填写“Orion 出差说明”，保持仅自己可见。问“舱位升级有什么要求？”。查看引用的章节、行号及检索过程中的补充片段数。

分块先尊重 Markdown 标题，再拆成小片段；命中后只补充同版本、同章节、当前有权限的相邻片段。设备领取属于另一个章节，不应被作为舱位的父上下文补入。

## 第五分钟：可复现评测

```sh
python evaluate.py --split dev --out reports/my-dev.json
python check_evaluation.py --report reports/my-dev.json --out reports/my-gate.json
```

门禁检查数据集、题数、关键指标、权限泄漏计数及相对 v4.1 基线的退步。缺失或 NaN 指标会失败。阈值是这个小型合成集的回归约束，需要在数据集变化时重新审阅。GitHub CI 默认跑离线检查；PostgreSQL 验证可以手动选跑。

说明 Recall@1 与 Hit@1 的区别：一道题有两篇相关文档，第一条命中其中一篇，Recall@1=0.5，Hit@1=1。不要用一次演示的成功率推断真实模型质量。

## 第六分钟：企业场景意识与个人项目取舍

切换 alice / bob 凭证展示不同资料范围；撤销资料后查看旧引用与会话隐藏。数据管理页可以导出自己的记录，先预览再清理。当前版本没有增加新基础设施或必需的云服务。

可选扩展：Dify / Coze 协议文件、真实 Embedding、神经重排、模型证据判断和 Langfuse。说明这些接口已提供，实际外部联调需要配置；当前测试记录把“未配置”与“通过”分开。

## 一条命令自检展示案例

```sh
python demo_walkthrough.py --out reports/my-showcase.json
```

脚本使用临时合成数据库，演示纠错、章节扩展、澄清、清理预览与执行。它不会修改日常使用的数据库或调用外部模型。输出记录是功能案例，不计入固定题集的准确率。
